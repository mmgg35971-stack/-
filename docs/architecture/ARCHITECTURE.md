# معمارية مترجم المانجا

هذا المستند يشرح كيف بُني النظام ولماذا. المراجع التفصيلية:
[SCHEMA.md](../database/SCHEMA.md) و[API.md](../api/API.md) و[SETUP.md](../setup/SETUP.md).

## 1. تقسيم النظام

```
┌────────────────────────┐      HTTPS + JWT       ┌──────────────────────────────────────┐
│ تطبيق Android (Kotlin) │ ─────────────────────▶ │ Supabase                              │
│ Compose · MVVM · Hilt  │                        │  • Auth (Google id_token)             │
│ Room (المسودات)        │ ◀───────────────────── │  • Postgres + RLS + دوال SECURITY     │
│ WorkManager (الرفع)    │   بيانات المستخدم فقط   │    DEFINER (القواعد التجارية)         │
│ عرض النص العربي محلياً │                        │  • Storage (bucket خاص)               │
└────────────────────────┘                        │  • Edge Functions (Deno)              │
                                                  └───────────────┬──────────────────────┘
                                                                  │ مفاتيح سرية على الخادم فقط
                                                  ┌───────────────▼──────────────────────┐
                                                  │ OCR: Google Vision                    │
                                                  │ الترجمة: Claude (claude-opus-5-5)     │
                                                  └──────────────────────────────────────┘
```

- **التطبيق** لا يحمل أي مفتاح سري. لديه فقط عنوان Supabase والمفتاح العام (anon) الذي
  لا يمنح شيئاً بدون جلسة، لأن كل الجداول محمية بـ RLS، وجداول الإدارة والأكواد مغلقة تماماً.
- **القرارات المهمة كلها على الخادم:** احتساب الحد اليومي، والخطة الفعالة، والتحقق من أكواد
  الهدايا، وصلاحية المدير. التطبيق يعرض النتيجة فقط.

## 2. اختيار التقنيات ولماذا

| المجال | الاختيار | السبب |
|---|---|---|
| الخادم | Supabase | Postgres حقيقي (معاملات، أقفال، RLS)، وAuth يدعم Google id_token، وStorage، وEdge Functions في مكان واحد. القواعد التجارية تُكتب كدوال SQL ذرّية، فلا تحدث مشاكل سباق في الحدود اليومية أو الأكواد. |
| الترجمة | Claude عبر واجهة `TranslationProvider` | جودة عالية في السياق الطويل، ومخرجات JSON بمخطط ثابت (structured outputs). المزوّد قابل للاستبدال من متغير بيئة. |
| OCR | Google Vision `DOCUMENT_TEXT_DETECTION` عبر `OcrProvider` | يعطي مربعات للكلمات والفقرات ودرجة ثقة، وهذا ضروري لتحديد الفقاعات ووسم النص غير الواضح. |
| عرض العربية | على الجهاز كطبقة فوق الصورة | محرك النص في Android يدعم التشكيل والوصل وRTL بشكل أصلي. الصورة الأصلية لا تُعدَّل أبداً، فيمكن المقارنة والتعديل في أي وقت دون إعادة توليد صور. |
| Android | Kotlin + Compose + Material3 + Hilt + Room + WorkManager + Coil + OkHttp | حسب المواصفات. Retrofit غير مستخدم لأن OkHttp مع kotlinx-serialization يكفي ويقلل الطبقات. |

## 3. تدفق ترجمة فصل

1. يختار المستخدم صوراً أو PDF. `PageImporter` يحوّل PDF إلى صور ويعيد ترميز الصور الكبيرة
   (أقصى عرض 2000px). تُحفظ المسودة في Room، فلا يضيع شيء إذا أُغلق التطبيق.
2. `UploadChapterWorker` (WorkManager) يستدعي `jobs-create` بمفتاح idempotency، ثم يرفع الصفحات
   إلى `chapter-pages/{uid}/{job}/original/NNNN.ext`. الرفع يُستأنف بعد انقطاع الشبكة.
3. `jobs-start` يتحقق من وجود مزودي OCR والترجمة، ومن اكتمال الرفع فعلاً في Storage، ثم يستدعي
   `start_translation_job`. هذه الدالة تقفل صف الاستخدام اليومي وتحتسب الفصل مرة واحدة فقط.
4. `jobs-worker` يسحب المهام بـ `FOR UPDATE SKIP LOCKED` حسب أولوية الخطة، وينفذ:
   OCR لكل صفحة، ثم ترتيب القراءة، ثم الترجمة على دفعات (8 صفحات أو 300 مقطع) مع القاموس
   وسياق العمل، ثم الإنهاء. كل صفحة تُعاد محاولتها حتى 3 مرات.
5. في النهاية يُنشأ إشعار داخل التطبيق. إذا فشل الفصل بالكامل دون أي صفحة مكتملة يُعاد الفصل
   إلى رصيد المستخدم تلقائياً.
6. القارئ يعرض الصورة الأصلية ويرسم فوقها النص العربي داخل كل مربع: لون الفقاعة يؤخذ من الصورة،
   ولون النص يُختار للتباين، والخط يُصغَّر تدريجياً حتى يتسع النص.

## 4. سياسة الاستخدام (الحد اليومي)

- اليوم هو **يوم UTC**، ويُعاد الضبط عند 00:00 UTC. التطبيق يعرض وقت إعادة الضبط بتوقيت الجهاز.
- يُحتسب الفصل **عند بدء المعالجة**، لا عند الرفع، ومرة واحدة فقط لكل `job` (`usage_counted`).
- إعادة المحاولة لصفحة أو لفصل قائم لا تحتسب فصلاً جديداً.
- الاسترداد: إذا انتهى الفصل بالفشل مع **صفر صفحات مكتملة**، يُعاد الفصل للرصيد (`usage_refunded`).
  الفصل المكتمل جزئياً يبقى محتسباً لأن المستخدم حصل على نتيجة.
- Free: 10، Pro: 100، Premium: غير محدود مع سياسة استخدام عادل (`fair_use` في `app_config`)
  توقف الإساءة الآلية وتطلب مراجعة، ولا تتصرف كحد خفي.
- الحدود ومزايا الخطط مخزنة في جدول `subscription_plans`، لا في كود التطبيق.

## 5. الاشتراكات وأكواد الهدايا

- الخطة الفعالة = أعلى خطة بين الاشتراكات النشطة (`effective_plan`)، وإلا Free.
- كود لنفس الخطة الحالية **يمدد** المدة. كود لخطة أعلى يبدأ **الآن**. كود لخطة أقل يُرفض
  أثناء وجود خطة أعلى (`higher_plan_active`) حتى لا يضيع على المستخدم.
- الأكواد تتكون من 12 رمزاً من أبجدية من 32 حرفاً (بدون 0 وO و1 وI)، أي 60 بت عشوائية.
  تُخزن كـ HMAC-SHA256 مع pepper سري، ويُحفظ تلميح فقط (`PRO-••••-••••-7KQ2`).
  الكود الكامل يظهر للمدير **مرة واحدة** عند الإنشاء، مع النسخ والمشاركة وتصدير CSV.
- الاستخدام محمي بقفل استشاري و`FOR UPDATE`. اختبار التزامن يرسل 20 محاولة متزامنة لكود
  واحد وينجح منها واحدة فقط.
- Google Play Billing لم يُربط بعد (المرحلة 6). الجداول جاهزة (`source = 'google_play'`،
  `play_product_id`)، وزر الشراء معطّل مع شرح.

## 6. الأمان

- **RLS على كل جدول.** الصلاحيات الافتراضية تُسحب من `anon` و`authenticated`، ثم تُمنح
  صلاحيات دقيقة على مستوى الأعمدة. مثلاً المستخدم يستطيع تعديل `user_edited_text` في المقطع،
  لكنه لا يستطيع تعديل `translated_text` أو `needs_review`.
- **دوال العمل** (`start_translation_job` و`redeem_gift_code` و`activate_admin`...) من نوع
  `SECURITY DEFINER`، وصلاحية تنفيذها لـ `service_role` فقط. تُستدعى من Edge Functions بعد
  التحقق من JWT.
- **المدير:** التفعيل يتم بكود سري مخزن كـ HMAC، مع حد 5 محاولات في الساعة وتسجيل في
  `admin_audit_logs` (جدول للإضافة فقط بـ trigger يمنع التعديل والحذف). كل استدعاء لـ `admin`
  يعيد التحقق من الدور. التطبيق يخفي المدخل فقط، ولا يعتمد على ذلك للحماية.
- **حدود المعدل** في Postgres (نافذة ثابتة): استخدام الأكواد 10 في الساعة، وتفعيل المدير 5 في الساعة.
- **حقن التعليمات:** نص OCR يُرسل للنموذج كبيانات JSON داخل وسم، مع تهريب `<` و`>`.
  تعليمات النظام تنص على تجاهل أي أوامر داخل النص. المخرجات مقيدة بمخطط JSON، وأي مقطع
  ناقص يُعتبر فشلاً.
- **على الجهاز:** الجلسة مشفرة بمفتاح AES-GCM في AndroidKeystore، ولا نسخ احتياطي
  (`allowBackup=false`). Storage خاص، والصور تُحمّل بـ JWT.
- **حذف الحساب** (`account-delete`) يحذف الملفات ثم المستخدم، وكل الجداول مرتبطة بـ `on delete cascade`.

## 7. ما لا يُفترض

- لا بيانات وهمية: كل الأرقام في الواجهة ولوحة المدير مصدرها قاعدة البيانات.
- لا زر بلا وظيفة: الميزات غير الجاهزة (الشراء) تظهر معطلة مع سبب واضح.
- لا فقدان للأصول: الصورة الأصلية لا تُعدّل، وتعديل المستخدم (`user_edited_text`) له الأولوية دائماً
  ولا يُكتب فوقه عند إعادة الترجمة.
