# تقرير فحص المشروع (PROJECT_AUDIT)

التاريخ: 2026-11-19. الفحص مبني على الكود الموجود فعلاً في الفرع `main`، وليس على أسماء الملفات.

## 1. الحالة الحالية باختصار

| الجزء | الحالة | الدليل |
|---|---|---|
| الخادم (Supabase) | منشور ويعمل على مشروع المالك | تشغيل "Deploy backend" رقم 4 نجح |
| قاعدة البيانات | 6 ترحيلات، RLS على كل الجداول، دوال SECURITY DEFINER | `backend/supabase/migrations/` |
| اختبارات قاعدة البيانات | قواعد العمل، والتزامن، والفوترة، والمدير | `backend/supabase/tests/` (تعمل في CI) |
| اختبارات الدوال | 13 اختبار Deno | `backend/supabase/functions/tests/` |
| تطبيق Android | يُبنى في CI مع lint واختبارات وحدة | `.github/workflows/android.yml` |
| تسجيل الدخول | بريد وكلمة مرور (أساسي)، وGoogle اختياري | `AuthClient`، `SignInScreen` |
| الخطط والحدود | الحد اليومي يُحسب على الخادم بتوقيت UTC، ولا خصم مزدوج | `start_translation_job` + اختبار تزامن |
| الترجمة | Claude (`claude-opus-5-5`) وGoogle Vision. **تحتاج مفاتيح المالك** | `_shared/providers.ts` |
| الشراء | Play Billing مع تحقق على الخادم. **يحتاج Play Console** | `billing-verify`، `BillingManager` |
| الإشعارات | FCM. **يحتاج Firebase** | `fcm.ts`، `PushService` |

## 2. المعمارية الموجودة

- **التطبيق:** Kotlin + Compose، وHilt للحقن، وRoom للمسودات المحلية، وWorkManager للرفع في الخلفية، وCoil للصور، وOkHttp للشبكة.
  كل شاشة تحتوي ViewModel الخاص بها، والمستودعات (`data/repositories`) هي الطبقة الوحيدة التي تتصل بالخادم.
- **الخادم:** Edge Functions بلغة Deno تتحقق من المستخدم ثم تستدعي دوال SQL ذرّية.
  الطابور في `translation_jobs` مع `SKIP LOCKED`، والعامل يعالج بأولوية الخطة.
- **الصورة الأصلية لا تُعدَّل أبداً:** الترجمة تُرسم على الجهاز كطبقة فوق الصورة (`TranslatedPage`).

## 4. نقاط القوة

- كل القواعد المالية (الحد، والخصم، والاشتراك، والمدير) على الخادم ومغطاة باختبارات، منها اختبار تزامن.
- لا أسرار داخل APK، والمفاتيح كلها أسرار في GitHub أو Supabase.
- تعديلات المستخدم محمية: العامل وإعادة الترجمة لا يمسّان `user_edited_text`.

## 5. المشكلات والمخاطر

1. **لم يُختبر على جهاز حقيقي بعد** مع ترجمة فعلية (تنقص مفاتيح Anthropic وVision).
2. Supabase المجاني يرسل رسائل بريد قليلة جداً، لذلك أُوقف "تأكيد البريد". قبل الإطلاق يجب ضبط SMTP خاص.
3. التكبير في القارئ لا يسمح بالتحريك، وقد يتعارض مع السحب بين الصفحات. (يُصلح في المرحلة F.)
4. نسخة التجربة موقّعة بمفتاح debug مشترك (مقصود). نسخة المتجر تحتاج مفتاح إصدار خاصاً بالمالك.

## 6. خطة الدمج

ترتيب التنفيذ في طلبات دمج صغيرة، كل واحد يُبنى ويُختبر في CI قبل الدمج:

1. **F + G + 16 (هذا الطلب):** أوضاع المقارنة الأربعة، والتكبير مع التحريك والمزامنة، وشريط تقدم القارئ والانتقال لصفحة،
   واحترام تقليل الحركة، وعرض القائمة في المكتبة مع التصفية حسب النوع. بدون تغييرات في قاعدة البيانات.
2. **C:** شاشة "ذاكرة القصة" لكل عمل (عرض وتعديل الملخص والشخصيات والأسلوب)، واقتراحات القاموس بانتظار التأكيد.
   يحتاج ترحيلاً لحالة المصطلح (`suggested` / `confirmed`).
3. **D + E:** صفحة "مشاريعي"، ومؤشر جودة الصفحة، وسجل التعديلات (جدول جديد `segment_edits`).
4. **H:** التكلفة حسب المزود والخطة، وحملات الأكواد بتقارير.
5. **J:** اختبار على جهاز حقيقي، ومفتاح الإصدار، وAAB للمتجر.

كل تغيير في قاعدة البيانات سيُوثّق في `docs/database/SCHEMA.md` مع ترحيل وخطة رجوع.
